Idea and origin

Not So Naive is an exact string-matching algorithm proposed by Christophe Hancart in 1992 and collected by C. Charras and T. Lecroq in Exact String Matching Algorithms. Given a text y of length n and a pattern x of length m, it reports every position where x occurs in y, including overlapping occurrences.

Like the naive algorithm, it slides a window of length m over the text and compares the pattern with the characters under the window. The naive algorithm compares from left to right and always moves the window one position. Not So Naive changes only two things: it compares the pattern positions in the order 1, 2, …, m−1 and finally 0, and, thanks to that first comparison of x[1], it can sometimes move the window two positions instead of one.

The name says it all: it is still a simple, brute-force style algorithm, but it is “not so naive”, because a single observation about the pattern lets it skip positions where no occurrence can start.

Preprocessing

Before searching, the algorithm compares the first two characters of the pattern once and fixes two shifts:

Conditionkell
x[0] == x[1]21
x[0] != x[1]12

k is the shift when x[1] ≠ y[j+1]. ell is the shift when x[1] = y[j+1], whether or not an occurrence was found. This phase takes O(1) time and space: one comparison, whatever the size of the input.

Searching phase

j ← 0
while j ≤ n − m:
    if x[1] ≠ y[j+1]:
        j ← j + k
    else:
        if x[2..m−1] = y[j+2..j+m−1] and x[0] = y[j]:
            report j
        j ← j + ell

Why a shift of 2 is safe

An occurrence can start at position j+1 only if y[j+1] = x[0]. The algorithm already knows y[j+1], because it has just compared it with x[1]:

  • If x[0] ≠ x[1] and y[j+1] = x[1], then y[j+1] ≠ x[0]: no occurrence starts at j+1, so moving ell = 2 is safe.
  • If x[0] = x[1] and y[j+1] ≠ x[1], then y[j+1] ≠ x[0] as well: moving k = 2 is safe.

In every other case the window moves only one position, exactly like the naive algorithm. Position j+1 is skipped only when it cannot be the start of an occurrence, so no occurrence is ever lost, overlapping ones included.

Complexity

  • Preprocessing: O(1) time and space, a single comparison of x[0] and x[1].
  • Search, worst case: O(n·m). At most n − m + 1 windows and at most m comparisons per window, for example y = aⁿ, x = aᵐ, where it never moves 2 and does the same work as the naive algorithm.
  • Extra space: O(1): only k, ell, j and i, excluding the stored positions.
  • Average: slightly sub-linear by a constant factor in the number of comparisons. The gain depends on the pattern: it is largest when x[0] = x[1], because then it moves 2 on the common event (a mismatch on x[1]), up to about half the comparisons of the naive search.

Comparison counts for a given input are an empirical measure; the asymptotic time complexity is O(n·m) for both algorithms, because Big-O ignores constant factors.

Base code

The whole algorithm in one method, without counters, trace or framework code:

public static List<Integer> notSoNaive(String y, String x) {
    int n = y.length(), m = x.length();
    List<Integer> positions = new ArrayList<>();
    if (m == 0 || m > n) return positions;

    if (m == 1) {                                   // no x[1]: compare x[0] only, shift 1
        for (int j = 0; j < n; j++)
            if (y.charAt(j) == x.charAt(0)) positions.add(j);
        return positions;
    }

    int k, ell;                                     // preprocessing, O(1)
    if (x.charAt(0) == x.charAt(1)) { k = 2; ell = 1; }
    else                            { k = 1; ell = 2; }

    int j = 0;
    while (j <= n - m) {
        if (x.charAt(1) != y.charAt(j + 1)) {       // first comparison fails
            j += k;
        } else {
            int i = 2;                              // compare x[2..m-1] with the text
            while (i < m && x.charAt(i) == y.charAt(j + i)) i++;
            if (i == m && x.charAt(0) == y.charAt(j)) positions.add(j);   // x[0] is checked last
            j += ell;
        }
    }
    return positions;
}
  • Guards: an empty pattern or a pattern longer than the text has no occurrences.
  • m = 1: there is no x[1], so every window compares only x[0] and moves 1.
  • Preprocessing: one comparison fixes k and ell.
  • Loop: runs while the pattern still fits (j ≤ n − m).
  • First comparison: x[1] against y[j+1]; on a mismatch the window moves k.
  • Rest: i walks x[2] … x[m−1]; x[0] is checked last; then the window moves ell.

The project’s own class, NotSoNaive, runs exactly this logic, but stores the positions in the SEED structures ListaCD and Secuencia and records the trace shown in the simulator.

Implementation notes

Business class NotSoNaive (pure Java, no indexOf, regular expressions or other matchers). Positions are collected in the SEED structure ufps.util.colecciones_seed.ListaCD (O(1) insertion at the end) and exposed through a SEED Secuencia for indexed access. The step-by-step trace of the simulator is produced by the same class, so the trace and the reported positions always agree. Reference: C. Charras & T. Lecroq, Exact String Matching Algorithms: Not So Naive.
